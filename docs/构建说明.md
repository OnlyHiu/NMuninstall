# 构建说明

本文档说明如何在 Windows 上从零构建 NMUninstall，以及 CI 中使用的命令。

---

## 1. 前置条件

| 组件 | 版本要求 | 安装方式 |
|------|---------|---------|
| Windows | 10 1809+ 或 Windows 11（x64 / ARM64） | — |
| Node.js | 22 或更高（LTS） | `winget install OpenJS.NodeJS.LTS` |
| Rust | stable，MSVC 目标 | 见 §1.2 |
| Microsoft C++ Build Tools | 任意近期版本 | 见 §1.3 |
| WebView2 Runtime | Win10 21H2+ / Win11 已内置 | 缺失时安装 Evergreen Bootstrapper |
| Git | 任意 | `winget install Git.Git` |

### 1.1 Node.js

```powershell
winget install --id OpenJS.NodeJS.LTS --exact
node -v     # v22 或更高
```

安装后需新开终端，让 `PATH` 生效。

### 1.2 Rust（MSVC 工具链）

下载 <https://win.rustup.rs/x86_64> 并执行：

```powershell
.\rustup-init.exe -y --default-toolchain stable --profile minimal --component rustfmt,clippy
```

验证：

```powershell
rustc -V    # 1.82 或更高（本项目 edition 2021，rust-version 1.82）
cargo -V
rustup show # 目标应为 x86_64-pc-windows-msvc
```

> 如果 `rustup show` 的 host 是 `*-pc-windows-gnu`，请执行
> `rustup default stable-x86_64-pc-windows-msvc` 切换到 MSVC 目标。

### 1.3 Microsoft C++ Build Tools

Rust 的 MSVC 目标需要链接器与 Windows SDK。推荐用官方安装器安装最小工作负载：

```powershell
# 下载引导程序
Invoke-WebRequest -Uri https://aka.ms/vs/17/release/vs_BuildTools.exe -OutFile vs_BuildTools.exe

# 静默安装 VCTools + Windows SDK
.\vs_BuildTools.exe --quiet --wait --norestart --nocache `
  --add Microsoft.VisualStudio.Workload.VCTools `
  --add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 `
  --add Microsoft.VisualStudio.Component.Windows11SDK.22621 `
  --includeRecommended
```

或者用 Visual Studio Installer 勾选「使用 C++ 的桌面开发」。

安装后确认 `vcvars64.bat` 存在：

```
C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat
```

> **提示**：`cargo` 会自动通过注册表发现 MSVC 工具链，**无需**手动执行
> `vcvars64.bat`。只有在自定义安装路径且未写入注册表时，才需要在
> 一个已加载 `vcvars64.bat` 的终端里运行 `cargo build`。

## 2. 安装依赖并开发

```bash
npm install          # 前端依赖
npm run tauri:dev    # 启动 Vite + Rust，热重载
```

首次运行会编译 Tauri 依赖（约 3–8 分钟，取决于机器），之后为增量编译。

### 2.1 单独运行前端

```bash
npm run dev          # 仅 Vite（需要 mock 后端，页面会显示加载失败态）
npm run build        # 类型检查 + 生产构建到 dist/
npm run preview      # 预览生产构建
```

## 3. 测试与静态检查

```bash
# 前端
npm run check:config  # 校验 src-tauri/tauri.conf.json 是否符合当前 CLI 的 schema
npm run typecheck    # tsc --noEmit
npm run lint         # ESLint
npm run test         # Vitest 单次运行
npm run test:watch   # Vitest 监听

# 后端
cargo fmt  --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml                       # 全部（含集成）
cargo test --manifest-path src-tauri/Cargo.toml --lib                # 仅单元
cargo test --manifest-path src-tauri/Cargo.toml --test parser_integration
cargo test --manifest-path src-tauri/Cargo.toml --test registry_integration
```

> `npm run check:config` 秒级完成，能在编译前抓出 `tauri.conf.json` 里的
> 拼写错误与失效字段（Tauri 2 移除了若干 v1 字段，例如
> `allowToChangeInstallationDirectory`）。不跑它的话，这类问题要等到
> `cargo check` 走到 build script 阶段才会暴露。

> `registry_integration` 会扫描**本机**注册表，断言全部是自洽性检查
> （ID 唯一、名称非空、耗时上限等），因此可在任意 Windows 机器上运行。
> 首次运行可能因杀毒软件实时扫描而偏慢，耗时上限已放宽到 5 秒。

## 4. 打包

```bash
npm run tauri:build
```

产物：

| 类型 | 路径 |
|------|------|
| NSIS 安装包 | `src-tauri/target/release/bundle/nsis/NMUninstall_1.0.0_x64-setup.exe` |
| MSI 安装包 | `src-tauri/target/release/bundle/msi/NMUninstall_1.0.0_x64_en-US.msi` |

`--profile release` 已启用 LTO、`opt-level = "s"`、符号剥离，体积和性能都做了优化。

### 4.0 只编译可执行文件（不打包）

首次打包时 Tauri 需要联网下载 NSIS / WiX 工具链（`github.com/tauri-apps/*-releases`）。
若网络不通，可先只验证可执行文件：

```bash
npm run build
cargo build --manifest-path src-tauri/Cargo.toml --release --features custom-protocol
```

> **`--features custom-protocol` 不能省。** 少了它，生成的二进制仍指向
> `build.devUrl`：进程能启动、窗口能出现，但页面会显示
> 「无法访问此页面 / localhost 拒绝连接」。`tauri build` 会自动带上该 feature，
> 手工 `cargo build --release` 不会。

### 4.1 打包配置说明

- `webviewInstallMode: downloadBootstrapper` —— 不捆绑 800MB 的离线 WebView2，改为按需下载引导程序
- `nsis.installMode: perMachine` —— 面向所有用户安装
- `bundle.targets: ["nsis", "msi"]` —— 两种安装包都产出
- 图标由 `scripts/generate-icons.ps1` 生成，见 §5

### 4.2 指定目标架构

```powershell
# x64
npm run tauri:build -- --target x86_64-pc-windows-msvc

# ARM64（需先 rustup target add aarch64-pc-windows-msvc）
npm run tauri:build -- --target aarch64-pc-windows-msvc
```

## 5. 图标

图标由脚本绘制生成，无需外部素材：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\generate-icons.ps1
```

输出到 `src-tauri/icons/`：各尺寸 PNG、Windows `StoreLogo` / `Square*Logo`、以及包含
16/24/32/48/64/128/256 的多尺寸 `icon.ico`。

如需替换为设计稿，删除该目录内容后放入同名文件，或直接用：

```bash
npm run tauri:icon path/to/1024x1024.png
```

## 6. 配置与数据位置

| 内容 | 路径 |
|------|------|
| 设置 | `%APPDATA%\com.onlyhiu.nmuninstall\settings.json` |
| 日志 | `%LOCALAPPDATA%\com.onlyhiu.nmuninstall\logs\nmuninstall-*.log` |

设置文件采用「写临时文件再原子重命名」，旧版本缺少的字段自动回落到默认值；
文件损坏时会被重命名为 `settings.json.corrupt` 保留现场，程序以默认设置启动。

调试日志级别：

```powershell
$env:NMUNINSTALL_LOG = "info,nmuninstall_lib=debug"
npm run tauri:dev
```

## 7. 常见问题

**Q: `cargo build` 报 `linker link.exe not found`**
A: Build Tools 未安装或未注册。用 §1.3 重装，或在已执行 `vcvars64.bat` 的终端中构建。

**Q: `rustup could not choose a version of rustc to run`**
A: 默认工具链未设置。执行 `rustup default stable`。

**Q: 界面空白 / 白屏**
A: 打开开发者工具查看控制台；通常是 `dist/` 未构建或 CSP 拦截。开发模式请用
`npm run tauri:dev` 而不是直接打开 `dist/index.html`。

**Q: 列表里没有某个程序**
A: 可能它使用了 UWP/MSIX 安装方式（本工具不扫描 `AppX`），或它是系统组件
（工具栏勾选「显示系统组件」后可见）。状态栏会显示跳过与去重数量。

**Q: 卸载后程序还在**
A: 若卸载器为 GUI 形式，工具会返回「已启动」状态而不会等待完成。请在卸载器窗口中
完成操作后点击刷新。静默卸载失败时部分安装器不返回错误码，因此本工具不会为
第三方安装器猜测静默开关。

**Q: 端口 1420 被占用**
A: Vite 使用 `strictPort`，请释放该端口（Tauri 依赖固定端口）。

## 8. CI

`.github/workflows/ci.yml` 定义三个任务：

| 任务 | 内容 |
|------|------|
| `frontend` | `npm ci` + typecheck + lint + Vitest |
| `backend` | `cargo fmt --check` + clippy + 单元测试 + 两个集成测试 |
| `bundle` | 依赖前两者通过后执行 `npm run tauri build`，并上传 NSIS/MSI 到 Artifacts |

`registry_integration` 只在 Windows runner 上运行，因为需要真实注册表。
